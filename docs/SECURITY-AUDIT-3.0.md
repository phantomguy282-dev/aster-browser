# Aster 3.0 pre-change security audit

## Scope and method
Reviewed every application main module in src/main (main, tabs, preload, security, store, downloads, account, updates, extensions, customization, migration, adblock, vpn), shell CSP/markup and existing tests. Static review plus npm registry vulnerability/outdated reports; no claim of a professional penetration test or proof packages are malware-free. This report precedes 3.0 application edits. Backup: `D:\dsh-workflow\projects\aster-before-3.0-audit.zip`.

Threat model: hostile web pages/subframes, malicious downloaded/imported packages, compromised shell/extension, corrupted or tampered local profile, async navigation races. Windows account compromise is not preventable by browser-side JavaScript; DPAPI protects cross-account at-rest secrets, not same-user malware.

## Findings and remediation plan
1. **High, extension consent integrity** — extensions.cjs install() inspects source before native consent but copies afterward; does not compare reviewed bytes/permissions to installed snapshot. init() trusts stored directory and reloads mutable files without recorded digest. A locally changed extension can run beyond the reviewed package. Stage immutable bounded copy before review, hash all contents, validate contained UUID directory, verify on every load; fail closed if changed. Add fixture tamper tests.
2. **Medium, private permission isolation** — main.cjs configureSession ignores isPrivate for permission decisions, reusing normal profile grants. Media is one combined permission. Introduce private in-memory per-origin decisions and camera/microphone separation, active-frame request identity, Ask/Block/Allow, revocation and closure cleanup.
3. **Medium, privileged IPC defense in depth** — main.cjs validates sender identity/frame but not exact UI URL; payload validation is ad hoc and unbounded for many commands. Preload forwards arbitrary action strings. Bind URL and frame identity, bounded plain JSON values/depth, explicit command names, rate-limit sensitive operations. Existing remote pages have no bridge; no direct web-to-Node exploit established.
4. **Medium, profile corruption/prototype keys** — store.cjs blindly Object.assign()s parsed JSON, lacks file size/schema checks, and can crash on non-array history/session. Reject dangerous keys and malformed core structures while preserving original on disk; bound input. Do not overwrite recoverable data silently. Atomic writes already exist but temporary path needs unique exclusive creation.
5. **Medium, navigation state race** — tabs.cjs async load errors may update stale tab URL/security display after newer navigation; close() permits asynchronous beforeunload-sensitive destruction. Track navigation generation/committed URL, force release closing views, test stale responses and resource cleanup. Same-origin SOP is supplied by Chromium; per-tab view alone is not a claim of distinct OS process for every site.
6. **Medium, private favicon leakage** — app.js uses remote favicon URLs in privileged shell session, outside private session and without page blocker. Fetch/cache bounded image within originating session or use privacy-safe local icon for private tabs; never attach page preload to shell.
7. **Medium, theme availability/spoofing** — customization.cjs blocks executable CSS and arbitrary selectors, but permits unbounded padding/font-size values on chrome ancestors. They can push security controls out of view despite protected child styling. Bound dimensions and protect chrome geometry; keep CSS only in shell.
8. **Low/medium, download safety** — downloads.cjs basenames/collision checks exist, but Windows device names/ADS/trailing dot semantics and repeated collision scan are not explicitly bounded. Sanitize Windows filenames and display executable warnings. Never auto-execute downloads. TOCTOU with same-user filesystem modifications is a residual OS threat.
9. **Medium availability/performance** — full state (history, wallpaper and theme library) sent on many load/progress events; synchronous JSON write and filter parse on main process. Coalesce state, bound source/cache totals, avoid duplicate writes and lazy-load nonessential services. Measure actual multi-tab processes rather than invented scores.
10. **Low, credential lifecycle completeness** — OAuth has sound fixed endpoints/PKCE/state/nonce/JWKS/secure storage, but no refresh flow and connected flag does not imply current valid token. Add controlled refresh and expiry status, bounded encrypted-file read, no token output. Missing owner registration remains external.
11. **Update trust** — existing Ed25519/HTTPS/hash/replay tests are solid; no production public key/feed or Authenticode certificate supplied. Install launches verified path after a second hash but no installation result/recovery tracking. Add pending-update recovery metadata and notifications; never generate fake production trust.
12. **Missing security UX/features** — security icon is noninteractive; no first-run/default association handling, protection-level controls or profile isolation manager. Implement supported policies, do not expose fake JavaScript/cookie/device controls or certificate data unavailable from APIs.

## Existing positives retained
Sandbox/context isolation, no Node for web content, CSP forbidding external scripts/connections, sender/frame checks, HTTP(S) navigation restrictions, default-denied permissions/device grants, isolated in-memory private partition, no TLS bypass, real request filtering, encrypted OAuth tokens, explicit import consent/read-only SQLite snapshots, update signatures and integrity, native confirmation for risky actions.

## Dependency/infrastructure evidence
`audit-3.0-dependencies.json`: 0 reported vulnerabilities. `audit-3.0-outdated.json`: empty at audit. Lockfile exists. Need license/integrity manifest and locked clean-build verification; a registry scan cannot prove absence of malicious packages. No gh/wrangler/netlify/vercel commands or named hosting/OAuth token environment variables were found in the initial metadata check. No secrets were printed and no accounts were created. Public deployment may need owner authentication; current installer is ~122 MB, so static-host file limits must be considered.

## Planned validation
Hostile-frame IPC and permissions, private isolation, stale navigation, extension tamper, unsafe filenames, malformed profile recovery, CSS geometry, DoH/WebRTC supported settings, first-run/default status, multi-tab cleanup; preserve prior 71-test suite and real browser integration. Findings above are static unless explicitly marked verified; remediation status goes in PROGRESS-3.0.md.
