# ASTER — is-a.dev custom domain setup (`aster.is-a.dev`)

**Status: prepared — awaiting owner registration.** The domain has NOT been registered, and no DNS verification has been performed. Nothing in this repository switches the site away from its current working URL.

## What the owner does (official process, no AI involvement)

The is-a.dev project explicitly asks that registration requests be written by the user, not generated by AI. Follow the official guides personally:

1. Read https://docs.is-a.dev/quickstart/ and https://docs.is-a.dev/guides/github-pages/
2. In your fork of https://github.com/is-a-dev/register, create `domains/aster.json` with a CNAME record pointing to:
   ```
   phantomguy282-dev.github.io
   ```
3. Submit the pull request and wait for it to be merged.
4. Do not consider the domain live until the merge has actually happened.

## What is already prepared here

- The website's asset paths are all **relative** — they work unchanged under both `/Aster-website/` and a root domain
- `robots.txt` and `sitemap.xml` exist; if the domain goes live, update the sitemap host and any canonical URLs from `phantomguy282-dev.github.io/Aster-website/` to `aster.is-a.dev` (a one-line change)
- GitHub Pages already has HTTPS enforced; after the domain is added in Settings → Pages, enable "Enforce HTTPS" once the certificate is issued
- GitHub Pages keeps the original `https://phantomguy282-dev.github.io/Aster-website/` URL working alongside the custom domain, so nothing breaks during the transition

## What to do after the registration PR merges

1. In the repo: **Settings → Pages → Custom domain** → enter `aster.is-a.dev` → Save. (This creates the CNAME file, or commit the CNAME file containing `aster.is-a.dev` and it will be picked up.)
2. Wait for the DNS check in Settings → Pages to pass.
3. Enable **Enforce HTTPS** (may take up to a few minutes for certificate provisioning).
4. Verify: open https://aster.is-a.dev/ and confirm pages, downloads, and release links work; also confirm the old URL still loads.

Do not complete these steps before the registration PR is actually merged — premature configuration will break DNS checks.
